# Crossword Clash

## Project Overview

Real-time multiplayer crossword puzzle game. Supports solo play with localStorage persistence and competitive multiplayer via Supabase Realtime Broadcast channels.

## Stack

- **Frontend**: React 19 + TypeScript + Vite 7 + Tailwind CSS v4 + i18next/react-i18next
- **Backend**: Supabase (Postgres + Auth + Realtime Broadcast)
- **Testing**: Vitest
- **Package manager**: pnpm

## Commands

- `pnpm dev` — start dev server
- `pnpm build` — type-check + production build
- `pnpm preview` — preview production build
- `pnpm test` — run unit tests (vitest)
- `pnpm test:watch` — run tests in watch mode

## Architecture

- **State management**: Single `useReducer` in `src/hooks/usePuzzle.ts` — no external state library. Derived values (activeClue, highlightedCells) via `useMemo`.
- **Supabase client**: Nullable singleton in `src/lib/supabaseClient.ts` — app works fully offline when env vars aren't set (only "Play Solo" available).
- **Puzzle import**: `@xwordly/xword-parser` parses .puz/.ipuz/.jpz/.xd files, then `src/lib/puzzleNormalizer.ts` converts to internal `Puzzle` type.
- **Persistence**: Solo mode uses localStorage for puzzle + progress. Multiplayer sessions (`crossword-clash-mp` / `crossword-clash-host`) are persisted to localStorage so players auto-rejoin on page refresh. Supabase handles multiplayer state via `claim_cell` RPC.
- **Multiplayer**: Supabase Broadcast channels for real-time cell claims. Conflict resolution: local check → server `claim_cell` RPC with row lock → broadcast. No deletion in multiplayer — correct letters are permanent. Host can close the room via `room_closed` broadcast, which boots all players back to the menu. Players leaving intentionally broadcast `player_left` so others see them disappear immediately.
- **After the finish** (navigation audit §2–3, `docs/navigation-audit.md`): `CompletionModal` makes Share the one primary action ("Share your time" after a daily), then the daily board and the challenge link, then an **Up next** list (`nextUpSuggestions` in `src/lib/nextUp.ts`, gathered by `useNextUp`: today's unsolved dailies mini → midi → large, else one unplayed classic, else the library; a daily or classic loads straight into the solo screen, whose once-per-puzzle refs reset on puzzle identity) and a "Race a friend live" row; "Back to menu" is the quiet exit and the importer is never offered (the header keeps "Load different puzzle"). Fresh puzzles come from the **picker** (`/pick-puzzle?intent=race|next`, `PuzzlePickerScreen`): today's unsolved dailies plus the classic grid (`ClassicList`, shared with `/classics`). `race` tears the finished state down and hands the pick to the host flow as `urlPuzzle`; `next` (the multiplayer host's "Next puzzle, same room") uploads the pick and calls `createNextGame` with *its* id, so the room code stays and nobody rematches the solved grid — the TV view's "Next puzzle" goes through its own importer. **Daily board**: the finish is parked in `GameContext.pendingDailyResult` (`PendingDailyResult`: entry + the submission promise); `DailyLeaderboardScreen` awaits it before its first fetch, shows the viewer's own row at once (`mergeOwnResult`), refetches on `visibilitychange`, and once the viewer has solved the slot shows "Solved in 1:42 · #n today" and races a fresh puzzle through the picker instead of replaying it. `BoardSignForm` is the one "sign the board" form (modal + board).
- **Exit warnings**: `useBeforeUnload` hook adds browser-native "Leave site?" dialog during active multiplayer sessions (lobby + playing screens for both player and host/TV views). Prevents accidental tab closure during games.
- **Route transitions** (`src/routeModules.ts`, `src/lib/transitionNavigate.ts`, `src/lib/viewTransition.ts`, `src/lib/routeCommit.ts`, `src/layouts/SiteFrame.tsx`, `src/components/NavigationProgress.tsx`, `src/components/ui/TransitionLink.tsx`): every code-split screen's import lives once in `screenModules`; the route config and `prefetchRoute(path)` (longest-prefix match, once per route) share it, so a chunk warmed on intent (`TransitionLink`'s pointerenter/focus/touchstart, `prefetchOnIntent(path)` on buttons) is already there when the route's `lazy` asks. `navigateWithTransition` (hook `useTransitionNavigate`) cross-fades the root (160 ms, `index.css`; UA keyframes kept so the fade never dips) with `.vt-site-bar` held still and `.vt-brand` morphing (the menu wordmark → the SiteBar logo); the game grid is never named. It only starts a transition once the chunk is loaded (150 ms budget, else a plain navigate — the page is frozen on the old snapshot while the update runs, so never wrap a download), skips under reduced motion / without the API, and catches all three ViewTransition promises. **Two gotchas**: `navigate(to, { flushSync: true })` only commits synchronously with the `RouterProvider` from `react-router/dom` (`main.tsx`), and a route's *first* render still commits a few ms after `navigate` resolves, so the update also awaits `nextRouteCommit()`, signalled from `SiteFrame`'s layout effect. `SiteFrame` is a pathless route around everything (legal pages and `/host` included) and also holds `<ScrollRestoration />` (top on push, restore on back/forward; a no-op on the full-height game screens) and the pending bar (`useNavigation().state === "loading"` for 150 ms+, reduced-motion safe).
- **Internationalization**: i18next + react-i18next with English and Spanish translations in `src/i18n/`. Language detected from localStorage (`crossword-clash:language`) → `navigator.language` → `'en'`. `LanguageSwitcher` component on menu screens. `tStatic()` for non-React contexts (window.confirm, alert). `<Trans>` component for rich text with embedded links. Spanish uses `→`/`↓` arrows instead of Across/Down.
- **Routing**: React Router with `createBrowserRouter`. `IndexRedirect` and `HostIndexRedirect` components determine initial route based on context state, URL params, and localStorage. **`/` is the cold-start resolver only** (it resumes a saved room or solo game before showing the menu): every in-app link or `navigate` that means "the menu" goes to `/menu` (`SiteBar`'s default `backTo` and logo, the error screens, screens that have just cleared their own state), so "Back to menu" never lands back in a finished puzzle or a stale lobby. **Room session expiry** (`sessionPersistence.ts`): `MpSession.savedAt` is stamped on save, kept on a re-save of the same room, and renewed by `touchMpSession` while the player is in the room; `loadMpSession` ignores sessions over 12 h old, and `useRejoinEffect` refuses a still-`waiting` room unless the session was touched within the hour. **Finished state**: `completionModalDismissed` (GameContext) starts true for a solo puzzle restored already finished and is set before the modal navigates away; the play screens then show `FinishedBar` (time chip + Share re-opens the modal + Leaderboard for a daily) in the header. **Important**: `extractPuzzleFromUrl()` clears `window.location.hash` as a side effect, so `GameProvider`/`HostLayout` call it during `useState` init and store the result as `urlPuzzle`. Route redirects must check `urlPuzzle` from context, never `window.location.hash`. Deep-linked screens (lobby, spectate, play) redirect to the index route when puzzle is null (triggers rejoin flow).
- **Classic library** (`/classics`, `ClassicLibraryScreen`): 46 public-domain puzzles from the 1924 *Cross Word Puzzle Book* (the first crossword book; Gutenberg #68267, .puz via crosserville.com) shipped as static files in `public/classic-puzzles/` with a **generated** `manifest.json` — never hand-edit it, run `pnpm build:classics` (`scripts/build-classic-manifest.mts`, which imports app TS via `scripts/ts-resolve-hook.mjs`). Each manifest entry carries the puzzle's `puzzleIdentity()` so the screen can show solved/PB badges from local solo stats without parsing files. Four of the book's 50 are deliberately excluded (#21, #34 slurs; #40 Klan-joke pseudonym; #42 swastika grid). Pure helpers in `src/lib/classicLibrary.ts`; the import hub previews the 4 smallest and links to `/classics`. "Play solo" follows the daily-mini path (`handleSoloPuzzleLoaded` → `/solo/play`); "Race friends" follows the daily-race path (`setUrlPuzzle` → `/host-game/name`). `classicLibrary.test.ts` verifies the manifest against the files on disk. The `/classics` route's `lazy` loads the manifest together with the chunk (`prefetchClassicManifest` → module cache read by `knownClassicManifest`), so the screen paints its cards on its first frame instead of a loading line that then shifts.
- **Daily feed** (`src/lib/dailyFeed.ts`, `useDailyMini`/`useIsTodaysDaily` in `src/hooks/useDailyMini.ts`): a day's daily can be published as a static file, `public/daily-puzzles/YYYY-MM-DD.json` (local calendar day, transfer format plus optional `theme`), written by `pnpm daily:add <date> <puzzle file> ["Theme"]`. A day with a file uses it; every other day, and any fetch failure, falls back to the bundled rotation in `dailyMinis.ts`. The answer is cached per day in localStorage (`crossword-clash:daily-feed`; "no file" is re-checked after 3h) so `isTodaysDaily()` stays synchronous. The menu hero shows a placeholder until the first answer of the day. The native apps (mobile mode) read the same feed from `https://crosswordclash.com` — `/daily-puzzles/` is excluded from the SPA rewrite so a missing day is a real 404, and `vercel.json` sets `Access-Control-Allow-Origin: *` there because Vercel's automatic one is missing from 404s — so publishing a day reaches web and apps at once, with no app release. **Admin schedule**: a day with no static file is answered by `api/daily.ts` (vercel.json rewrites `/daily-puzzles/:day.json` there; Vercel serves real files first) from the Supabase `daily_schedule` table, whose RLS only exposes days that have started (≤ UTC date + 1). The constructor manages it from /studio through the `studio-schedule` edge function (STUDIO_TOKEN-gated, service-role writes). **Daily slots** (`DailySlot = "mini" | "midi" | "large"` in `dailyFeed.ts`): the midi (original 9×9s, `public/daily-puzzles/midi/`, `--slot midi`, rewrite to `api/daily.ts?slot=midi`, migration `20261018000000`) and the large are second and third dailies beside the mini; both have no fallback and no tile on a day with nothing published. `defaultSlotFor`: ≥ 11 wide → large, ≥ 8 → midi, else mini. The large is a second daily for original 15×15 themed puzzles. Static files live at `public/daily-puzzles/large/YYYY-MM-DD.json` (`pnpm daily:add --slot large …`), vercel.json rewrites `/daily-puzzles/large/:day.json` to `api/daily.ts?slot=large`, and `daily_schedule`/`daily_results` are keyed by `(day, slot)` (migration `20261017000000_daily_slots.sql`). The large has **no bundled fallback**: a day with nothing published has no large, and the menu shows no second tile (`useDailyPuzzle("large")` → `null`). Feed cache is per slot (`crossword-clash:daily-feed:large`). `todaysDailySlot()`/`useTodaysDailySlot()` say which daily a loaded puzzle is; each slot has its own leaderboard (`/daily/leaderboard` and `/daily/leaderboard/large`, `leaderboardPath()`), and the completion share caption names the slot. The studio's DailyQueue shows both queues and defaults the slot by grid size (`defaultSlotFor`: ≥ 11 wide → large).
- **SeedGrid construction engine** (`src/lib/seedgrid/`, CLI `pnpm seedgrid`): makes original puzzles the Ingrid way. The grid math is deterministic and browser-safe (so a future studio UI can reuse it): `dictionary.ts` (`WORD;SCORE;tags` lists, per-(position,letter) bitsets), `grid.ts`, `solver.ts` (`FillEngine`: arc consistency + MRV search, approvals per slot, global rejections, no dupes or shared runs longer than `maxShared` — 3 everywhere, engine-filled entries only; locked themers are the constructor's call — a one-step heatmap via `cellOptions()`), `layout.ts` (seed placement: same-length seeds paired in mirrored rows, one row between parallel seeds at minimum, `pairedPlacements`/`freePlacements` enumerate every pairing or crossing; `shapeSkeleton` adds blacks where the heatmap is worst), **grid standards** in `grid.ts` (`meetsGridStandards`: no 2×2 black block anywhere, corners white from 11×11 up — minis/midis need their corner blacks) that every skeleton builder enforces, `skeletonSearch.ts` (`enumerateSkeletons`: column-by-column construction with row pruning, the only way to shape stacked themers; `searchSkeleton`: annealing scored by the engine heatmap), `skeletonFinder.ts` (the studio's Lay out pipeline: random draws — `placement: "paired"` whenever `canPair` says the seeds mirror, so no long unthemed slot ever faces a themer; the free draw only for sets that cannot pair — → enumerated skeletons ranked by heatmap → annealing → lower score floors; reports the floor the layout fills at, which the studio surfaces), `audit.ts`, `ipuz.ts` (speed clues ride in an extension key). Claude only picks among proven-viable candidates, reviews the fill, and writes clues (`scripts/seedgrid/make.mts`, structured output via `claude.mts`; `claude-opus-5-5` by default). Word lists: `pnpm seedgrid:dict` builds the gitignored `base.dict` on the MIT Crossword Nexus Collaborative Word List's 0–100 scale (its catch-all 50 tier demoted to 47; numeral entries dropped; its long phrases are what make seeded midis fillable), with ENABLE + FrequencyWords filling in missing words. Frequency may only **lower** the score of single words (`scoring.ts`: rare ones cap at 45, below the usual 50 floor); phrases stored without spaces (GOATCHEESE) are naturally rare as tokens, so frequency never touches them, and `blocked.dict` from LDNOOBW; the committed `lively.dict` (Claude-proposed phrases, grow it with `pnpm seedgrid:lively`) and `rescore.dict` (hand overrides) layer on top. Spread the Word(list) is CC-BY-NC, so it is not used. **Two lists**: `base.dict` scores everyday words with FrequencyWords (CC-BY-SA data, private use only); `production.dict` uses only the Collaborative Word List (MIT), ENABLE (public domain) and SCOWL levels 10–70 (permissive; level 80 brings in UKACD) for commonness (`levelCap`/`levelScore` in `scoring.ts`). `pnpm seedgrid:studio-dict` writes both to `public/seedgrid/` plus `NOTICES.txt`. The studio loads `/seedgrid/words.dict` in dev and, in every other build, `words-production.dict` from the public `seedgrid` Supabase Storage bucket (`pnpm seedgrid:upload-dict` publishes it with NOTICES.txt; no deploy needed); `VITE_SEEDGRID_WORD_LIST` overrides both, and studio builds drop the private `words.dict` from their output unless it is named there. The CLI picks with `SEEDGRID_WORD_LIST=production`. Output lands in `artifacts/seedgrid/<date>-<slug>/` (`puzzle.ipuz` for `pnpm daily:add`, plus `review.md` with every curation/review decision). **Daily large** (`pnpm seedgrid:large`, `scripts/seedgrid/large.mts`): a themed 15×15 from a theme spec with no browser session — `--theme "Football x music" --seeds "touchdown under, goal post malone, …" [--title] [--allow-shared] [--min-score 50] [--seeds-floor 48] [--no-llm] [--dry-run]`, or `--batch docs/large-puzzle-themes.json [--only slug]` (any JSON/YAML list; the backlog's `entries[][0]` are the seeds) which continues past failures and writes a summary table. Pure helpers in `themedLarge.ts` (tested): `validateSeeds` (same-length pairs plus at most one centered odd entry; themers sharing a run longer than 3 are refused unless `--allow-shared`), `nestedEntries` (an engine entry of 4+ letters inside another entry is a duplicate; a contained entry no longer than `MAX_SHARED` is an allowed shared run, as in `audit.ts`) and `scoreFill` (quality = capped list scores, sub-tier entries charged double, partial-looking entries penalized unless the list scores them 60+, nesting penalized, `wordlists/theme-bonus/<slug>.dict` rewarded; a word from the committed `wordlists/ban.dict` throws the fill out and is also passed to the engine as a rejection — keep that list to junk, slurs and the genuinely crude; double-meaning words are ordinary fill). The CLI loads the Ingrid wasm engine in Node with the studio's `public/seedgrid/words-production.dict`, runs `findSkeleton` for `--layouts 2` skeletons (keeping the one whose tightest slot has the most options, then fewest flagged entries in quick fills, then quality per entry — a skeleton with a two-option slot dies on the first rejection there; at the floor it reports; `--seeds-floor` defaults to 48 because 47 is the list's demoted catch-all tier, and four stacked 13/14s need `--seeds-floor 45`), fills `--fills 24` times with a tightening pass (re-fill at the requested score everywhere but the slots that provably need the floor), shortlists 3 block-free fills, and Claude picks, rejects "must" entries (up to three refills, each pick the best fill so far that avoids every rejection, and a word the layout forces is kept and recorded for the editor; after the audit gate, local refills and swaps, the fill that ships gets a closing review whose leftover "must" entries are recorded for the editor); audit blocks (nested entries) are rejected and refilled the same way and fail the theme if they cannot be cleared; then each flagged entry gets a local refill (its crossings' ring, or the ring beyond, refilled at the requested score, kept when the fill scores better) and Claude may swap flagged entries for engine-listed alternatives that fit the crossings. Clues come from `cluesRequest` with the themers as question-mark puns and a content rule (nothing crude, sad or gross, no dialect mockery), then a Claude content review and a rewrite of what it flags. Output: `puzzle.ipuz`, `review.md` (seeds, skeleton + floor, every fill with its weak entries and audit blocks, every decision, clues table) and `studio.json` (a `StudioState` for a future studio import). **Editing a finished puzzle** (`scripts/seedgrid/puzzleDir.mts` reads a `pnpm seedgrid` folder — puzzle.ipuz + session.json — or a `pnpm seedgrid:large` folder — puzzle.ipuz + studio.json — into one shape and writes every file that exists back, so they never drift): `pnpm seedgrid:timely <dir> <date> [docs/daily-hooks.json] [--max 3] [--dry]` offers the puzzle its publish day's hooks (`docs/daily-hooks.json`, researched per batch as `docs/daily-hooks.md` describes: sports, holidays, anniversaries, never grim news) and lets Claude rewrite at most a few clues where one fits, each vetted by `clueProblems` before it is written (pure parts in `timely.ts`: `timelyRequest`, `vetRewrites`); `pnpm seedgrid:reclue <dir> easy|medium|hard [--only-missing] [--context "…"]` rewrites the clues at a register with the CLI's fix passes and the shared content review (`contentReviewRequest` + `CONTENT_RULE` in `cluePrompt.ts`, which large.mts uses too); `pnpm seedgrid:refix <dir> <WORD> [--floor 50] [--apply] [--tries 12]` rejects a forced entry and refills its neighbourhood with the Ingrid engine — its crossings, then theirs, then one ring more, stopping once a candidate's weakest replacement scores 60 — ranks candidates by weakest new entry, then `scoreFill`, then the size of the change (`refix.ts`: `ringSlots`, `blankSlots`, `rankCandidates`), and with `--apply` writes the fill back, records the rejection and drops the changed slots' clues for a `reclue --only-missing`; `pnpm seedgrid:crosscheck <from> [<to>] [--strict]` reads the published feed (`public/daily-puzzles/{,midi/,large/}<day>.json`) and reports the **three same-day rules** (`crosscheck.ts`): a title is never an entry of its puzzle, every clue is present, at most `CLUE_MAX` characters and never gives its answer away, and the same day's mini, midi and large share no entry of 4+ letters (three-letter glue is allowed). Run it over a stocked range before opening the PR. **Studio** (`/studio`, `StudioScreen`, dev builds only, or set `VITE_STUDIO=1`): an Ingrid-style editor. It runs Ingrid's own engine, `ingrid_core` (MIT, Rust), vendored in `engine/vendor/ingrid_core` with a one-line `Instant` patch (see its PATCHES.md; the CLI and its CC-BY-NC list are left out) and wrapped by `engine/src/lib.rs` (`fill`, and `options` = arc-consistent counts per slot for the heatmap). `pnpm build:engine` (needs rustup's wasm32 target + wasm-bindgen-cli) writes the **committed** bindings to `src/lib/seedgrid/wasm/`, so the web build never needs Rust. `ingrid.ts` speaks our Grid/slot ids and adds `classify` (Ingrid's good/nogood: a timed full fill per candidate); `engine.worker.ts` + `engineClient.ts` run it off the main thread (Stop = terminate the worker). Editor state is the pure `studioState.ts` reducer: typed letters are locked, engine letters aren't, and Fill always refills from the locked letters; approvals are keyed by slot geometry so renumbering keeps them; the draft lives in localStorage. **Clue drafting**: prompts and checks live in `cluePrompt.ts`, shared with the CLI; the studio sends them through the `studio-claude` edge function (`studioClaude.ts`), which requires the `STUDIO_TOKEN` Supabase secret in an `x-studio-token` header (the constructor pastes it into /studio once; a copy is in `.env.local`), and shares the narrator's rate limiter, usage log and monthly cap (Opus 5.5 is priced at a deliberately high ceiling in `narratorBudget.ts` + its Deno mirror). Drafts get the CLI's checks and one fix pass; clues typed or picked by hand are recorded in `editedClues` and never overwritten. **Saving**: every non-blank puzzle is filed under "My puzzles" (`studioLibrary.ts`, localStorage `crossword-clash:studio-puzzles`, newest first, capped at 50; each entry is the whole studio state with its own `id`), and versions keep clues. **Play test** opens the grid in the solver through the normal `#puzzle=` link (`toTransferPuzzle` in `ipuz.ts`); entries without a clue show "(no clue yet)". **Daily queue** (`DailyQueue.tsx`, `studioSchedule.ts`): shows the next two weeks of `daily_schedule` and schedules the open puzzle on a chosen day (a snapshot; needs a full grid, a title and a passing clue for every entry). The studio token lives in `useStudioToken` and is shared by every panel that needs it. **Studio sign-in** (`studioAuth.ts`, `useStudioAccount`, `StudioAccount` in the top bar): Apple or Google, studio only (players stay anonymous). An existing anonymous user gets the provider linked (`linkIdentity`, needs "manual linking" on in Supabase) so its history stays; if that account already exists the return trip says `identity_already_exists` and `resumeStudioSignIn` signs in to it instead. Providers not switched on in Supabase (public `/auth/v1/settings`) show disabled. Accounts listed in `studio_admins` (added by hand) use Claude drafting and the daily queue without the token: `studioHeaders` sends the account's access token, and `_shared/studioAuth.ts` (`studioAllowed`) accepts either the token or a non-anonymous admin. Apple's OAuth client secret expires every six months; regenerate it with `pnpm apple:client-secret`. Ingrid's app layer is proprietary: rebuild its behavior, don't copy it.
- **Solver accounts (optional)**: every visitor stays an anonymous Supabase user; on the website they may also sign in with Apple or Google to keep a public username and their solve history. `src/lib/account.ts` is the shared auth module (the studio's `studioAuth.ts` re-exports it): `signInWith` links the provider to the current anonymous user (`linkIdentity`, needs "manual linking" on in Supabase) so `players.user_id`, `daily_results` and `play_sessions` keep their owner; an `identity_already_exists` return trip signs in to the existing account instead; `resumeSignIn` answers once per page load; `signOut` ends the session and `useSupabase` immediately starts a fresh anonymous one. `deleteAccount` ("Delete account" in the sheet, one confirm) calls the `delete-account` edge function, which deletes the user's rows in the tables that only store the id (`play_sessions`, `narrator_sessions`, `daily_results`, `players`; `games.host_user_id` is nulled) and then the auth user, which cascades `profiles`, `solves` and `studio_admins`; a new table holding a user id must be added there or reference `auth.users ON DELETE CASCADE`. `accountsAvailable()` is false in mobile mode (the apps' webview can't host the providers' pages) and without Supabase, so those builds show no account UI at all. Profiles live in the `profiles` table (`username` 3–20 chars `[A-Za-z0-9_]`, unique on `lower(username)` via a generated `username_lower`, public read, owner-only writes, non-anonymous JWT required); rules mirrored in `src/lib/username.ts` (`validateUsername`, reserved names, `suggestUsername` from the provider name). `AccountProvider` (`src/contexts/AccountContext.tsx`, inside `RootLayout`) owns `useAccount` (user + profile) and the one `AccountSheet` (sign-in → account → `UsernamePicker` with live availability); `openAccount({ returnTo: "/" })` is how play screens open it, since the menu finishes the return trip and opens the picker after a first sign-in. Entry points: `AccountMenuRow` on the menu and `onSignIn` on `CompletionModal`, both benefit-led and only for anonymous visitors. A signed-in solver's username prefills `HostNameScreen` and `JoinGame` (still editable), and saving it also becomes the remembered player name. **Solve history (phase 2)**: anonymous play keeps best times and streaks in localStorage (`soloStats.ts`) and nothing changes for it. For an account, the `solves` table (migration `20261017300000_solves.sql`; owner-only RLS, non-anonymous JWT) is the source of truth: one row per (user, `puzzleIdentity()`, local `completed_day`) with `title`, `source` (`daily` | `nyt` | `other`), `mode` (`solo` | race mode | `import`) and nullable `seconds` (a shared-grid versus/co-op finish has no personal time but still counts for streaks). Nothing stores a counter: `src/lib/solveHistory.ts` derives best times (min `seconds` per puzzle), the daily streak (days with a solo finish or a daily finish — the same rule `recordSoloCompletion`/`recordDailyPlay` use locally), the NYT streak (days with an `nyt` finish) and the synced count from the rows, so every device shows the same numbers. Writes go through the `record_solves(jsonb)` RPC (SECURITY INVOKER, user_id from the JWT; on conflict keeps the best time, fills a missing title, lets a real finish replace an `import` row). `AccountProvider` calls `ensureSolveHistory(userId)` when an account appears: it loads the rows (paged), then `uploadLocalHistory` once per account per device (`crossword-clash:solves-uploaded`): local best times become `import` rows dated today with source `other` (so they touch no streak) and a still-alive local streak becomes one `legacy:daily:<day>`/`legacy:nyt:<day>` marker row per day of its current run (`longest` isn't shown anywhere, so it isn't carried). A failed upload isn't marked done and is retried. Readers use `useSolveHistory`/`useStreaks`/`useBestTimes` (`src/hooks/useSolveHistory.ts`), which fall back to local stats while anonymous, loading or offline: the menu and leaderboard streak chips, `PuzzleReadyScreen`'s NYT streak, the classic library's solved/PB badges, and the account sheet's "N solves synced" line. On completion, `SoloPlayScreen` (fresh finishes only — `useSoloTimer` says `fresh`; a reload reads the loaded history) and `MultiplayerPlayScreen` (once per game id) call `recordSolve`, which judges the finish against the loaded rows (`judgeSolve`: previous best, new best, streaks as of that day), merges it optimistically and then writes; the modal's best/streak rows show that outcome when it exists, else the local result. The privacy policy's "Accounts (optional)" paragraph describes what a solve row holds.
- **Play insights** (`src/lib/playInsights.ts` tracker, `usePlayInsights` in the solo + multiplayer play screens, `playInsightsClient.ts` sender): one `play_sessions` row per visit to a puzzle, upserted by id on completion, on page hide, and on leaving the screen (keepalive fetch to PostgREST with a cached anonymous-auth token). It records progress, active time (input gaps capped at 30 s), wrong letters (from `rejectedCell`), and per clue the first-focus and solve times, wrong letters, and how many letters came from crossings or other players. Each row also carries `platform` (`platformLabel()`: OS + browser, or "<OS> app") and `signed_in`. `narrator_sessions` gets one row per TV narrator start attempt from `useNarrator` (`sendNarratorSession`: requested vs. answering engine, `connected`/`failed`/`budget`). These feed inferred difficulty, drop-off and unfair-clue analysis. ## Game Modes

- **Solo**: Import puzzle → play locally → progress saved to localStorage and Supabase (if connected).
- **Host Game (Player View)**: Import puzzle → enter display name → multiplayer game created with 6-char share code → lobby (with QR code for easy joining) → start when 2+ players joined. Host can close the room at any time from lobby or playing screen. Refreshing the page auto-rejoins.
- **TV / Host View** (`/host`): Read-only spectator display. Creates a game room without joining as a player. Shows grid, clue list with strikethrough for completed words, scoreboard, room code + QR. Host can start game when 2+ players join and close the room at any time. Per-clue speech announcements via Web Speech API or ElevenLabs TTS. Optional AI narrator mode provides snarky gameshow commentary (see AI Narrator section).
- **Join Game**: Enter share code or scan QR code → join lobby → play when host starts. Refreshing the page auto-rejoins (session persisted to localStorage).

## Multiplayer Input Flow

```
Keypress → useGridNavigation → wrappedInputLetter
  0. Lockout check: Date.now() < lockedUntil? → skip (letter input only; navigation still works)
  1. Local check: cell already filled? → skip
  2. Correct letter? → no: visual reject + apply lockout timeout (if configured)
  3. Optimistic: dispatch INPUT_LETTER with playerId
  4. Server: claimCellOnServer()
     → success: broadcast cell_claimed to others
     → fail: dispatch ROLLBACK_CELL
```

## Wrong Answer Timeout

Host configures a lockout penalty in the lobby before starting (Off, 1s, 2s, 3s, or 5s). Setting is broadcast to all players via `game_started` event payload. When a player enters a wrong letter, all letter input is blocked for the configured duration. A countdown overlay appears on the grid during lockout. Navigation (arrows, tab) still works. Solo mode is unaffected. Settings are defined in `src/lib/gameSettings.ts`, UI in `src/components/GameLobby/TimeoutSelector.tsx`, overlay in `src/components/LockoutOverlay.tsx`.

## AI Narrator (Multi-Backend)

TV/Host view supports an optional AI narrator that provides live gameshow commentary. The narrator is separate from per-clue TTS announcements — when a narrator is active, `speak()` becomes a no-op and the narrator handles all commentary.

### Narrator Backends

Three backends implement the `NarratorBackend` interface (`src/lib/narrator/types.ts`):

1. **ElevenLabs Agent** (`elevenlabs-agent`): ElevenLabs Conversational AI agent. Voice/personality configured in ElevenLabs dashboard. Edge function `agent-auth` returns signed WebSocket URL. Requires `ELEVENLABS_AGENT_ID` and `ELEVENLABS_API_KEY` env vars.
2. **OpenAI Realtime** (`openai-agent`): OpenAI Realtime API with GPT-4o. Built-in voice synthesis via WebSocket, PCM16 audio playback via `AudioContext`. Edge function `openai-agent-auth` creates ephemeral token. Requires `OPENAI_API_KEY` env var.
3. **Claude + TTS** (`claude`): Claude generates commentary text, then speaks via ElevenLabs TTS. Maintains conversation history client-side. Edge function `narrator-claude` proxies to Claude API. Requires `ANTHROPIC_API_KEY` env var.

### Settings

- `TTSEngine` (`"browser" | "elevenlabs"`) controls per-clue TTS voice when no narrator is active.
- `NarratorEngine` (`"elevenlabs-agent" | "openai-agent" | "claude" | null`) controls the AI narrator. `null` = no narrator (legacy per-clue announcements).
- Legacy `engine: "agent"` in localStorage auto-migrates to `narratorEngine: "elevenlabs-agent"`.
- Settings stored in `src/lib/ttsSettings.ts`, UI in `src/components/TTSControls/TTSControls.tsx`.

### Gating

No devtools localStorage gate — a regular visitor on `/host` can turn the narrator on from the TTS settings modal (shown whenever Supabase is configured, i.e. `isElevenLabsAvailable()`). Only available in TV/Host view (`/host` routes via `HostLayout`); never spawned for player or host-as-player views.

### Cost control (owner budget cap)

- **Pure math**: `src/lib/narratorBudget.ts` (typechecked + unit-tested) prices `api_usage` ledger rows into a month-to-date USD estimate and an over/under-cap boolean. Mirrored for Deno in `supabase/functions/_shared/narratorBudget.ts` — keep the two in sync.
- **Server guard**: `supabase/functions/_shared/budgetGuard.ts` queries rolling month-to-date spend from the Neon `api_usage` table (via the existing `DASHBOARD_DATABASE_URL`) and, once estimated combined Anthropic+ElevenLabs+OpenAI spend reaches `NARRATOR_MONTHLY_USD_CAP` (default 20), refuses every narrator/TTS auth endpoint with HTTP 402 `{error:'narrator_unavailable', reason:'budget'}`. Fails open only when spend genuinely can't be measured.
- **Graceful client**: backends throw the `narrator_unavailable:budget` sentinel; `useNarrator` surfaces `budgetExhausted` (no cascade/retry loop) and `HostSpectateScreen` shows a friendly "taking a break" banner (`tts.narratorBudgetPaused`). Narrator stays off.
- **Demo allowance**: first-time TV hosts get a few sampled events (`src/lib/narratorDemo.ts`, metered in localStorage) on the cheapest Claude path even while over budget; the server independently caps demo grants per IP via the `narrator_usage` table.
- **Rate limiting**: per-IP via `_shared/rateLimit.ts` on all narrator auth endpoints.

### Session Lifecycle

`useNarrator` hook (`src/hooks/useNarrator.ts`) manages connection via `createNarratorBackend()` factory. Connection starts when game becomes active, stays alive through game completion so narrator can react to the winner. Auto-disconnects after 30s idle. Immediately disconnects on: room close, back to menu, new puzzle, engine change, mute, unmount, or `gameStatus → "waiting"`.

### Events

`GAME_STARTED` (puzzle metadata + player names), `CLUE_COMPLETED` (player, clue details, scores, remaining), `LEAD_CHANGE` (new/previous leader + scores), `GAME_COMPLETED` (winner + final scores). Event builders are pure functions in `src/lib/narrator/events.ts`.

### ElevenLabs Agent Specifics

- Mic muted via `setMicMuted(true)` — all input is text.
- **Idle chatter prevention**: Dashboard system prompt must include "NEVER ask if the user is still there. NEVER initiate conversation unprompted. Only speak when you receive a game event."
- **Speech interruption prevention**: Events arriving while agent is speaking use `sendContextualUpdate()` instead of `sendUserMessage()` to avoid cutting off the agent. When agent returns to listening, accumulated context is prompted with `sendUserMessage("Please comment on the recent events.")`.
